# Media V2 UI regressions and release checks

Updated 20 November 2026 for the Windows x64 popup.

Use the installed Windows build and the fork for the previous YASB behavior. Use the pinned Serpantinum full popup for the intended sequence and relationships between elements. The user's preference governs the alignment of both information fields. The installed build and the reported candidate both say 2.0.9. Their identical executable launchers load different code from `lib/library.zip`. The installed archive starts with SHA-256 `b5a622a0` and the reported archive with `73bee01c`. All 13 installed Media V2 UI modules match the fork at `0d01fb26`. [GitHub reference](https://github.com/PhamCarrot/yasb/tree/0d01fb268802cd0728ed89a63e5fad42ddad9218) · [Shell reference and capture inventory](MEDIA_V2_PLAN.md#baseline-and-evidence)

| Reported or reproduced issue | Expected behavior and regression check |
| --- | --- |
| Opening collapsed 23 effects into five. Artwork, text and controls arrived as a block. Bands rose as one row. | At 200 ms artwork and text have different progress, controls and bands are still waiting. At 650 ms all ten bands are moving from different vertical offsets. The cover, divider and presets have distinct exits. Interrupt a close and reopen from that frame. |
| Switching presets could put the handles at their final gains before the first frame. The visual backend echoed the new curve synchronously. An APO destination refresh could also cut off travel. | Click Flat → Bass, then reverse to Treble mid-flight. Observe the handle between endpoints, the complete committed curve immediately, and continuity after an identical writer notification. Check visual mode and two views sharing a disposable APO writer. A drag during travel changes only the edited band and requires Apply. |
| Alignment changes moved the output-device and Via captions away from the center. Long labels could overflow their boxes after elision. | With one player, the rendered device name and Via caption each center in their badge. With two players, the device stays centered and the selector caption ends before the arrow on the right. Repeat with short and overflowing names and preserve full names for accessibility. |
| The multiple-player selector looked like a static badge because its themed dropdown arrow was missing. | Verify the arrow with the built-in style and the user's theme. Check that a theme can replace it. Switch between one and two sessions and open the real selector menu. |
| The menu interpreted an ampersand as a shortcut, and a generated suffix could match another track's real name. | Open a menu containing `R&B Radio` and sessions titled `Song`, `Song` and `Song (2)`. Check the literal ampersand, distinct labels and selected session identity. |
| The title tooltip retained the previous track after a player closed or the next player was still loading. | Start with a named track and album, then switch to a loading player and close the last player. The tooltip must follow the visible title in both states. |
| Tabs lost their crossfade and Audio cards appeared together. Rapid reversal could make an outgoing card jump, or expose hidden Audio content and start its timer over Equalizer. | At 100 ms both page position and opacity must be between endpoints. Balance, channels and dynamics appear in order. Reverse during a card reveal and also before the next event-loop tick. After settling or reopening, exactly the selected page is visible and hidden Audio has stopped polling. |
| The header action appeared instantly on navigation. Lyrics reserved an empty action slot beside Retry. | On Equalizer → Audio, Reset gains width over the 400 ms transition while the tabs stay still. In Lyrics, only a failed or missing lookup exposes Retry at the right edge. Within Equalizer, keep the draft action stable during a drag and keep the full caption on interrupted reopen. |

### Checks future sessions can repeat

1. Record the fork commit, the executable and library hashes, and the theme used. Keep the previous build available for comparison. Use the same screen size, fonts, scale, playback state and number of sessions. Confirm the icon asset and compiled Python modules in the final build.
2. Capture an early frame, an intermediate frame and a settled frame for each changed interaction. Use real timer advancement as well as controlled intermediate states. A test that only checks the final slider value or the existence of an animation also passes when the slider jumps.
3. Exercise ordinary clicks, keyboard tab changes, a rapid second selection, direct Equalizer → Lyrics, and close/reopen during motion. Inspect colors, handle coordinates, hit targets, hidden pages, timers and lyric subscriptions. Use a temporary profile and fake audio endpoints for repeatable checks.
4. Compare the actual Windows build with both default styling and the user's media rules. Load the theme fonts before judging alignment. Look at the text, ellipses and chevron in the rendered frame. Record display scale and whether the evidence is a Qt widget capture, a Windows window capture or a human playback observation.
5. Keep the newer fixes when restoring an older visual behavior. Check the early seek waveform, rounded end tabs, full caption after reflow, large lyric lists and manual Apply. A passing functional suite and a fast first paint each answer a different question from a visual comparison.
