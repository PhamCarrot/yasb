# PERF-001 — measured image-work reuse

Completed locally 17 November 2026. No Git writes, live player/capture/APO/profile/system mutation, global installation or ETW session. This is a measured local raster/worker optimization; it does not establish native presented FPS.

## Changed and decisions

Two Media V2 views displayed the same 4096×4096 fixture but decoded it twice and prepared its blur/palette twice. A worker-side shared cache now reuses those outputs: **2 decodes + 2 preparations → 1 + 1**. Existing per-view tasks still own demand, coalescing, generation/lifetime and publication. No new executor, capture owner or GUI work was added. Border and ambient motion remain intact.

The cache holds at most8 entries and32MiB of accounted retained images/metadata/keys. Content+extent identifies decode work; pixel layout/palette/DPR/color profile and radius identify generated backgrounds; file identity/size/timestamps identify custom images. ICC identity is hashed. Independent QImage snapshots and immutable palettes preserve mutation isolation. Worker locking coalesces identical requests; diagnostics read an immutable snapshot without waiting on that lock. Existing four-entry view caches remain.

Review caught a pixel-only accounting defect before completion: tiny compressed PNGs can retain large metadata. The final cache counts retained ICC, text, palettes and keys. Actual compressed2MiB-text and4MiB-ICC cases preserve fidelity while being rejected by a1MiB cache. Exceptions remain retryable, oversized assets do not evict useful entries, and no compressed input is retained as a cache key.
