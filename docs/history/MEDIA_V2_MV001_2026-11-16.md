## Change and boundaries

After startup failed, the old backend kept `_started=True` and closed its source. Refresh cleared the error without restarting. Windows source close is terminal, so resetting a flag alone could not recover.

The same shared backend now owns one tracked startup task and an explicit replacement factory. Retries create a fresh default Windows source; concurrent callers join startup, and cancelling one waiter does not cancel it. Injected sources remain supported; failure recovery requires an explicit factory and never guesses a constructor or silently falls back to Windows.

Retirement invalidates the generation before closing subscriptions/cancelling work, clears session selection/readiness and removes timeline demand. Events, metadata and commands capture source lifetime so stale results cannot affect replacement sessions, including reused IDs. Healthy refresh preserves manual selection; shutdown drains owned tasks. A dispatched native action may already have occurred; retirement suppresses its late notification rather than claiming to undo it.

Production change: `src/core/widgets/services/media/backend.py`. Fourteen new cases in `tests/widgets/test_media_backend.py` cover retry through start/refresh, empty inventory, concurrent calls and waiter cancellation, construction failure, partial native registration cleanup, injection without native fallback, reused IDs, stale metadata/events/actions, shutdown and healthy refresh.
