## Changed and decisions

Independent immutable integer-millisecond lyric documents support bounded LRC, enhanced LRC, YRC, Lyricsfile 1.0 safe YAML/JSON, plain text and instrumental states. Preserve spaces, equal starts, overlaps, word order and optional ends. LRC offset is ignored with a warning; Lyricsfile offset is retained without guessing its unresolved semantics. Limits: one MiB input, 5000 rows, 16384characters per row,30000 words, seven-day times, 16 YAML levels and 100000 parse events. Reject aliases, anchors, duplicate/non-string keys, custom tags and unsupported scalars. Preflight repeated timestamps before allocating expanded words. Two-field YRC markers and unmarked prefixes retain text. No AGPL code/assets copied or translated.

Pure provider adapters rank title/artist/version/duration matches. LRCLIB first, then observed NetEase cloud/web/lyric fallback; this deterministic sequential policy deliberately differs from the reference's concurrent race. Album can be a playlist. LRCLIB Lyricsfile takes precedence over LRC/plain. NetEase is explicitly labeled an undocumented interface; no public-contract or live-availability claim. Title-only media can import locally; automatic lookup waits for artist metadata.

One application-owned QtNetwork manager/service holds interest tokens and one actual reply OR parse slot. At most64 views, eight pending imports,32 cached records/16MiB accounted document/query/detail bytes. Active interested states are separately bounded by the64-view limit. Fixed provider hosts, same-origin redirects, identifying app/version/project UA, exact JSON media types (NetEase text/plain exception), one MiB reply,8s transfer/10s wall timeout,250ms sequential spacing (minimum200ms). Honor Retry-After with0-30% jitter and at most two automatic retries for delays at most60s; valid longer cooldowns remain honored. Nonfinite malformed values fall back to2s instead of permanently blocking a provider. Ready cache TTL30min; missing/error30s. Review reproduced structured plain rows bypassing limits and13dense documents reported16.38MB while retaining80.29MB; both are corrected. The shared plain-row validator covers YAML/JSON and timed/plain text. Conservative Python instance/dictionary/container/string/integer accounting is frozen into each document during parser construction, keeping GUI cache admission constant time. Five regressions cover structured row/length limits and dense retained-object accounting. Independent current probes exit0:5000rows/16384characters accepted unchanged,5001/16385 rejected in YAML/JSON; dense4999line/29994word fixture accounts9053900bytes versus8445996retained tracemalloc and7794010deep-reachable bytes. Five additional ASCII/astral/plain/LRC/eLRC probes remain conservatively accounted. The16MiB cache now admits only one such dense document.

Last interest aborts a reply and clears queued demand/retries. The actual reply slot lasts until finished acknowledges abort. Parser work runs off the GUI thread and retains its slot until it actually returns; generation checks discard hidden/replaced/A-to-B-to-A results. Local import supersedes provider intent and shares the same actual parse slot. Replaced pending imports resolve false. Shutdown invalidates intent and awaits both reply acknowledgement and actual parser drain before retiring the shared owner; a cancelled drain waiter cannot expose a successor. Main application shutdown drains this owner before cancelling other tasks.
